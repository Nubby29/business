# UI/UX Audit — Phase 6 Visual Redesign

## Objective

Move the homepage from a generic card-and-icon agency layout toward a distinctive B2B automation consultancy experience that demonstrates systems visually and makes the offer easier to understand.

## Major problems identified

- Excessive repeated card components created visual monotony.
- Generic decorative SVG icons did not communicate the actual service.
- Blue accent color was used too frequently and lost hierarchy.
- Hero looked like a standard SaaS landing page rather than an automation specialist.
- Example Systems relied on icons instead of demonstrating actual workflows.
- Process section used decorative icons instead of showing the progression from workflow to system.
- Dark sections and rounded cards created too much visual weight.
- Contact form felt like a traditional lead form instead of a simple workflow diagnosis.
- Industry categories were more prominent than the repetitive-work problems the service actually solves.

## Phase 6 redesign

### Hero

- Reframed headline around eliminating repetitive manual work.
- Replaced decorative workflow card with an actual system visualization: input → process → system → action.
- Added a manual-vs-automated comparison.
- Reduced decorative elements and strengthened hierarchy.

### Problem section

Added four operational problem categories:
- Lead handling
- Reporting
- Monitoring
- Operations

This makes the value proposition concrete before presenting pricing.

### Services

Replaced three identical cards with an editorial three-column service layout.

- Automation Audit
- Starter Automation
- Business Automation System

The middle service receives visual emphasis without claiming it is objectively the best choice.

### Who this is for

Changed from generic industry cards to a workflow-first explanation while retaining relevant examples for recruiting/staffing, professional services, and operations teams.

### Capability demonstrations

Removed decorative icons and replaced them with actual miniature automation diagrams showing:
- Lead intake
- Scheduled reporting
- Website monitoring

These are explicitly labeled demonstrations, not customer results.

### Approach

Replaced the previous collection of proof cards with a more editorial principles layout:
1. Start with the workflow
2. Use the right level of technology
3. Design for failure
4. Keep it maintainable

### Process

Replaced four decorative SVG icons with visual system artifacts:
- Workflow map
- System flow
- Test passed
- Monitored

The four steps remain Discover → Design → Build & Test → Operate.

### FAQ

Changed from boxed accordion cards to a lightweight editorial accordion with clearer hierarchy.

### Contact

Simplified the lead experience around the user's current process instead of asking for an automation specification.

## Accessibility

Retained:
- Skip link
- Visible keyboard focus
- Semantic labels
- Native form controls
- Mobile navigation
- Escape-to-close mobile menu
- Reduced-motion support
- Status feedback
- Responsive layouts

Still required before launch:
- Browser/device QA
- Contrast verification
- Keyboard-only walkthrough
- 200%/400% zoom test
- Real lead destination

## Brand direction

The visual language now emphasizes **business systems visualization** rather than generic AI decoration:

- workflow diagrams
- system states
- process maps
- data movement
- operational labels
- restrained blue accents
- strong typography
- whitespace
- technical detail without cyberpunk styling

## Important content rule

No fabricated:
- testimonials
- customer logos
- customer results
- case studies
- performance claims

Capability demonstrations are clearly identified as demonstrations until real customer evidence exists.
